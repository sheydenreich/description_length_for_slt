Reading. The genuine Bayes code of the valid alignment is LONGER than the label-only code at 1024
targets (1526-2370 against 1342 bits) where the plug-in code gains 983 bits, and its regret against
the plug-in's final fit grows at ~270 per ln n against the plug-in's 8. This is the prediction of the
Hessian/Fisher analysis (reports/stage1_ioi/curvature_gpt2.txt): the subspace family is regular on its
1024-dimensional Grassmannian, so a Bayes code must pay for the prior mass of the right 4-plane, of
order lambda ln n with lambda up to 512, while the plug-in finds the plane along Fisher-free
directions at no charge. At 8192 targets the Bayes code has concentrated (IIA 1.00, 3707 bits against
a label-only code of ~10,700) but still trails the plug-in by ~1175 nats. The untrained-twin code at
1633 bits is the prior predictive (chains never leave the prior: nothing to learn), and the wrong
locus gains nothing. Conclusion for the plan's Bayes-code line: on alignment families the Bayes
learning coefficient is real, large, and not the quantity that makes an explanation short; the
plug-in's kappa = (1/2) tr(F H^-1) is.
